    ステップ5：Agentic RAG エージェントを作成する¶

    概要¶

    このステップでは、要求された SKU が特定のブランチで在庫切れの場合に適切な代替製品を提案する Substitute Finder Agent（代替品検索エージェント）を作成します。

    SKU Availability Agent がリアルタイムの Kafka 状態に依存するのとは異なり、このエージェントは Agentic RAG（検索拡張生成） を使ってエンタープライズ製品ドキュメントを推論します。

    Substitute Finder Agent の目的¶

    このステップの目的は、静的なルールやハードコードされたマッピングに依存せず、製品仕様の意味的な理解と構造化された推論を組み合わせてエージェントが動作できることを実証することです。

    エージェントの動作¶

    1. ドキュメントから製品仕様・説明を読み込む
    2. 要求された SKU の特性（カテゴリ、ティア、フォームファクター、主要機能）を理解する
    3. セマンティック類似検索で類似製品を特定する
    4. 推薦理由とともに 2〜3 件の代替 SKU を返す

    Note

    このエージェントは Kafka と直接やり取りしません。在庫状況の確認は前のステップで作成した SKU Availability Agent が担当します。

    Substitute Finder Agent を作成する¶

    エージェントの定義はリポジトリ内の YAML ファイルとして提供されています。

    手順¶

    1. YAML ファイルを確認する

    前のステップでダウンロードした Substitute_Finder_Agent.yamlファイルを使用します。

    2. エージェントをインポートする Bobに以下の指示をしてください。 

    resources/Substitute_Finder_Agent.yamlの名称に"ご自身のイニシャル_"を付け加えて、
watsonx Orchestrateにインポートしてください

    3. エージェントをデプロイする

    インポートが完了したら、エージェントをアクティブ状態にするためにデプロイします：

    1. watsonx Orchestrate UI を開く
    2. Manage agents で Substitute_Finder_Agent を選択する
    3. Deploy ボタンをクリックする
    4. Pre-deployment summary ウィンドウで再度 Deploy をクリックする

    Tip

    デプロイには 1〜2 分かかる場合があります。ステータスが Active になるまで待ってください。

    製品カタログをアップロードする¶

    エージェントの作成・デプロイが完了した時点では、まだエンタープライズドキュメントへのアクセス権がありません。次の手順で製品カタログをナレッジソースとして登録します。

    製品カタログについて¶

    このハンズオンでは、内部製品カタログを表す 1 つの Word ドキュメント（product-catalog.docx）を使用します。このドキュメントには複数の製品エントリが一貫したフォーマットで記載されており、セマンティック検索と類似マッチングに適しています。

    リポジトリの tutorial assets フォルダ内に product-catalog.docx があります。

    カタログに含まれるサンプル製品（例）：

    • LAPTOP-DELL-XPS-15
    • LAPTOP-HP-SPECTRE-X360
    • その他のラップトップ・モバイル製品

    これらの製品は、カテゴリ・プロセッサークラス・メモリ・ストレージ・使用目的ティアなどの属性を意図的に共有しています。この重複により、エージェントはセマンティック類似度を通じてそれらを適切な代替品として特定できます。

    アップロード手順¶

    1. 左上のメニュー > ビルド からSubstitute_Finder_Agentの管理画面に移動する

    2. 知識ソースからソースを追加するをクリック

    3. 新しい知識をクリック

    4. ファイルをアップロードする

    ファイルのアップロード をクリックして 次へ を選択します。

    product-catalog.docxをアップロードします。

    5. Next をクリックする

    6. ナレッジソースを設定する

    設定項目 値
    名前 enterprise_documents
    説明 製品カタログ（代替品推薦用）

    名前の重要性

    名前は必ず enterprise_documents に設定してください。エージェントの YAML 定義がこの名前でナレッジソースを参照しています。

    7. 保存 をクリックする

    インデックス処理が完了するまで待ちます（数分かかる場合があります）。ドキュメントがセマンティック検索に利用可能になったことを確認してください。

    エージェントを単独でテストする¶

    次のステップでスーパーバイザーエージェントと統合する前に、このエージェントを単独でテストします。

    テスト1¶

    製品カタログから LAPTOP-DELL-XPS-15 のエントリを取得し、主要な属性を一覧にしてください。

    期待される動作：
    エージェントがカタログエントリを取得し、ドキュメントに定義された属性を一覧表示します。

    テスト2¶

    LAPTOP-DELL-XPS-15 は在庫がありません。製品カタログを使って類似のラップトップを提案してください。
    期待される動作：
    エージェントが HP-SPECTRE-X360 を推薦し、カタログから共通属性を使って推薦理由を説明します。

    次のステップ¶

    Substitute Finder Agent の作成が完了したら、ステップ6 に進んでスーパーバイザーエージェントを作成します。
